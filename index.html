01 The setup

🏦

The bank

BLACKVAULT Private Bank. Login form, account dashboard, side-gate PIN. Everything runs on a real server with a real SQLite database. The money is fake. The vulnerability is not.

🔫

The flaw

The server builds its SQL query by gluing your typing straight into the command string. Whatever you type becomes part of the command. That is SQL injection, one of the oldest and most exploited bugs on the web.

⚒️

The tool

Burp Suite sits between your browser and the bank as an interception proxy. Every request and response stops at your desk for editing before it moves on. Nothing about the page is out of reach.

Where Burp stands

🖥️Your browser
🛡️BURP SUITEpause · read · edit · forward
🗃️BLACKVAULT server

Your browser thinks it is talking to the bank. The bank thinks it is talking to you. Burp is in the middle, and everything that passes through is yours to rewrite.

03 Why it worked

The server glues your typing into a SQL command. Watch the payload take the command apart, piece by piece.

What actually broke, and what did not

    

      

        
Broke

        
    
          
  • The trust boundary between data and command. Your text stopped being data and became SQL.
    • 
          
  • The bank's authentication. The server itself counted you as admin because its own query said so.
    • 
        

      

      

        
Did not break

        
    
          
  • No real bank, account or person. The database is fake, lives in memory, and resets itself.
    • 
          
  • No encryption was cracked. TLS still worked perfectly; Burp simply stands at the endpoint where traffic is readable.

Lab 1 · Steal the vault codes with Repeater

      
The bank's statement endpoint takes an account number and drops it into SQL unquoted. Repeater lets you replay and rewrite that request until the database hands over things it should not.

      
    
        
  1. In Burp, load the statement URL below and let it reach the server once.
    2. 
        
  2. Find it in Proxy → HTTP history, right-click, Send to Repeater.
    3. 
        
  3. Replace the account value with the UNION payload, press Send, read the response.
    4. 
      

      
targetGET /api/statement?account=2

      
payload-1 UNION SELECT id, code, note, 0 FROM vault_secrets

      
Why four columns? The real query returns id, kind, amount, note. UNION only works when both sides line up, which is why your first guesses may come back as SQL errors. Those errors are the database talking to you.

05 The fix

  

    

      
Vulnerable (what this bank does)

      
query = "SELECT ... FROM users
  WHERE username = '" + u + "'
  AND password = '" + p + "'"

      
Your text becomes command.

    

    

      
Hardened (one switch away)

      
stmt = db.prepare(
  "SELECT ... FROM users
   WHERE username = ? AND password = ?")
stmt.bind([u, p])

      
Your text stays data. Always.

    

  

  

    
Do not take our word for it. Flip the bank to the  and fire the same payload. It bounces off, because the database never sees your text as SQL.
